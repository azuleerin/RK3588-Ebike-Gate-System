# AGENT_RULES_FOR_CRASH_DEBUGGING.md

> 🚨 **最高指令：稳定性压倒一切**
>
> 当前系统在运行 AI 流水线时出现底层硬挂死（Hard Lockup，Ping 不通/SSH 断连）。
> **在查明原因并修复之前，严禁进行任何新功能开发。**
> 所有 Agent 必须严格遵守以下规范进行排雷与重构。

---

## 一、最小化执行单元（隔离排查）

绝对禁止把所有的模块（解码、RGA、NPU、LPRNet、MQTT）串在一起跑！

必须将流水线拆解为独立的最小可执行测试单元。

**排查顺序**：只跑 MPP 解码 → 只跑 RGA 转换 → 只跑 NPU 推理 → 只跑 LPRNet。

每个 Agent 认领一个模块，进行 24 小时不间断长跑（使用长视频或循环推流）。
哪个模块先触发死机，就锁定哪个模块。

- 如果是 MPP 导致死机，就彻底放弃硬解；
- 如果是 RGA 导致，就禁用 RGA。

---

## 二、内存操作与堆空间分区（严防越界）

**堆空间隔离**：严禁全局 new / malloc 乱飞。必须评估引入 cgroup（MemoryMax）限制主程序的内存峰值，
防止应用层的内存泄漏或疯狂申请（OOM）拖死整个 Linux 内核。

**DMA-BUF 严格校验**：涉及 DMA-BUF、mmap、物理地址指针传递的地方（如 MPP 传给 RGA，RGA 传给 NPU），
必须校验文件描述符（fd）的有效性和大小边界。任何越界写都会直接导致总线挂死。

**指针安全**：C++ 代码中严禁裸指针跨线程无锁共享。必须使用 `std::shared_ptr` 或严格的生命周期管理。
释放内存后必须将指针置空。

---

## 三、独立可视化验证程序

**不要用打印日志来验证图像算法！**

必须编写一个独立的、不带业务功能（不推 MQTT、不测速）的 Visualizer（可视化 Demo）。

这个程序只负责：读视频 → 推理 → 画框/画 ROI → `cv::imshow` 或存图。

必须支持人工肉眼验证：确认检测框、ROI 裁切、字符识别是否在视觉上正确，
杜绝"日志正确但内存已损坏"的情况。

---

## 四、极致的运行日志与打点

**分级日志**：使用标准的日志库（或严格封装 printf），分为 INFO（正常流转）、WARN（降级/重试）、ERROR（核心错误）。

**关键路径打点**：在每次分配内存、进入推理前、出来后、跨线程传数据前后，
必须写 Log 记录 `[时间戳][线程ID][函数名][动作]`。

**落盘保存**：日志必须同步写入本地磁盘文件（如 `logs/run.log`），
确保即使 SSH 断连，重启后也能查到断连前最后几秒的日志。

---

## 五、严格的 Git 提交与 Diff 审查

**小步快跑**：每次只改一个逻辑点，绝不大段重写。

**强制审查**：Agent 每次提交代码前，必须自行执行 `git diff`，并将差异（Diff）输出到对话中供人类（我）审查。
审查重点：是否新增了未捕获的异常、是否修改了指针、是否分配了内存。

**回滚基线**：每次跑长跑测试前，必须打一个 Git Tag。死机后立刻回滚到上一个 Tag，
通过二分法排查是哪个 Commit 引入的死机。

---

## 六、强制注释规范

所有涉及底层（MPP、RGA、RKNN）的内存传递、指针操作、结构体对齐的代码，必须写详细注释。

注释必须说明：这块内存的物理属性是什么（CPU 内存还是 DMA-BUF）、数据格式是什么（NV12/INT8）、
由谁申请、由谁释放、生命周期跨越了哪些线程。

不要写废话注释，写"**为什么这么写**"的注释
（例如：`// 这里必须按偶对齐，否则 RGA 会写坏下一行内存触发内核 Oops`）。
