# v2.0-gate-4ch —— 4 路大门架构 / NPU 三核全局调度 / Web 控制台 3.0

> **交付对象**：RK3588 边缘 AI 计算终端（小区大门 4 路场景，路口非机动车感知）
> **代码基线**：`v2.0-gate-4ch`（本 tag）
> **所有数字均为板端实测**，无一条估算。

## 一句话

**单块 RK3588 跑通 4 路并发，9.44 小时 / 827,280 帧无人值守长跑零崩溃、内存零增长。**

## 本版核心内容

### 1. 4 路大门架构（单板）
- 新增 `gate_main.cc`：单进程多路入口，`--ch "ch1:源:角色"` 逐路声明
- 4 条独立流水线跑在同一块板子上：近景带 PP-OCR 车牌识别 ×2 + 高位 IPM 测速 ×2
- 两种口径均可复现：`run_4ch_gate_demo.sh`（4 独立进程）/ `run_4ch_gate_single.sh`（单进程 + 全局 NPU 线程池）
- **小区大门压测实测**（1 路实时 RTSP + 3 路本地回放，来源 `docs/PPT_ASSETS.md`）：
  各路交付 FPS 14.3 / 18.6 / 17.8 / 19.9，NPU 三核 85% / 89% / 65%，CPU 34.5%，4 路 RSS 合计 392 MB 且 10 分钟零增长
  （注意：这一组与下面 1.5 的 A/B **不是同一批数据**，源和参数都不同，别直接对比；1.5 才是同源同参的严格对比）

### 1.5 两种拓扑的公平 A/B：单进程 vs 4 进程（2026-11-16 新增）

**为什么要比**：4 路起 4 个进程时，进程之间共享不了 RKNN 上下文 —— 同一颗核被两个进程抢，
谁先谁后由 NPU 驱动决定；识别（24 ms）和检测（30 ms）在队列里权重一样，近景的识别会被压住。
`rk_gate` 把 4 路收进**一个进程**，共用一条**按优先级排**的队列（识别永远在检测前面）。

**口径**：同板、同源（4 个本地文件）、同参、先后紧挨着跑；统计窗口剔除"板上有别的进程在跑"的时段。

| 指标 | A：4 个独立进程 | B：**1 个进程（rk_gate）** | 变化 |
|---|---|---|---|
| **NPU 三核占用合计** | 173.2% | 173.7% | **持平（同样的算力）** |
| 各核占用 | 70.1 / 78.1 / **25.0**% | **19.1** / 77.2 / 77.3% | 一核空转 → 按需分配 |
| **4 路交付 FPS 合计** | 58.87 | **73.24** | **+24%** |
| ch1 近景/车牌 | 11.11 | **15.35** | **+38%** |
| ch2 高位/测速 | 17.62 | **19.71** | +12% |
| ch3 近景/车牌 | 17.06 | **18.62** | +9% |
| ch4 高位/测速(4K) | 13.08 | **19.56** | **+49%** |
| CPU 总占用 | 67.5% | 65.7% | −3% |
| **4 路 RSS 合计** | 253 MB | **194 MB** | **−23%** |

> **硬件没多买一颗，同样的 NPU 算力多跑出 24% 的画面，内存还省了 23%。**
> 复现：`scripts/run_4ch_gate_ab.sh 600 20` → `logs/gate_4ch_ab/summary.txt`

### 2. NPU 三核全局调度
- `npu_pool` 统一调度三个 NPU 核：Core0 / Core1 = 检测双实例，Core2 = PP-OCR 识别
- 最忙核在 4 路并发下仍有 35% 余量，检测与识别**不再抢核**
- 定频（performance governor）后整帧 P99 抖动 −7.7%，单帧 max −16.7%

### 3. 硬件加速公平 A/B/C 对比（新增答辩数据）
三组跑同一条命令、同样 600 帧画面，都保持【检测 + PP-OCR 识别】全开，每组只关一个硬件单元：

| 组 | 配置 | FPS | 解码 ms | 预处理 ms | CPU |
|---|---|---|---|---|---|
| **A** | MPP + RGA + NPU 全开 | **35.10** | 0.30 | 1.67 | **23.9%** |
| **B** | 只关 MPP | 22.50 | **14.34 (47×)** | 4.46 | **98.1% (4.1×)** |
| **C** | 只关 RGA | 29.90 | 0.36 | **5.17 (3.1×)** | **103.3% (4.3×)** |

> 关掉硬解，每路多烧 0.75 个核；**12 路就多烧 9 个核，而一块板只有 8 个。**

### 4. Web 控制台 3.0
- **开关真联动板端**：MPP 开关点下去，板端解码后端真的从 MPP 切到 FFMPEG（不是前端假开关）
- RTSP 输入源自适应 + 断线自动重连 + 不可达检测（1.5 秒内给出明确报错）
- 实时展示 FPS / CPU / NPU 三核负载 / 内存曲线

### 5. 内存绝对平线
- 48,000 帧活堆净增 **+31 KB**，RSS **+96 KB**
- 泄漏斜率从 **+0.612 KB/帧** 降到 **+0.0006 KB/帧**，**降了 1000 倍**

### 6. 改动的回归证明（每一处都有前后对拍）

| 改动 | 回归方法 | 结果 |
|---|---|---|
| **cls 空间自动判别**（模型若去掉 Sigmoid，板端自动补一次；概率形态则不重复套） | 4 组数据集 × 改动前后各跑一遍 `rk_eval`，逐图比框数 + 每个框的类别/分数/坐标 | **4/4 完全一致**（含 1664 张街道图上的 84 个检测，逐框分数与坐标零差异） |
| **识别路径去掉 46 KB/次 的 memcpy** | 同一段视频关掉车牌缓存让每帧都裁，两边落盘的 ROI **逐字节**比对 + 识别日志逐条比对 | **44 张 ROI 逐字节一致**、**68 条识别日志逐条一致** |
| **并行检测路径的 RGA 目标缓冲补 16 行余量** | 与串行路径同一套余量规则（`rk/rga_pad.h` 全工程唯一来源） | 消除 RGA 非整数倍缩放时的越界写（实测溢出 2 行 = 3840 字节） |
| **核绑定 CLI 统一**（`--det-core` / `--ocr-core`，旧写法保留为别名） | 解析后打印"原文 → 掩码 → 核列表"，并行/串行共用同一份掩码 | 修掉「`--npu-core` 在 `--npu-pipe≥2` 时被静默忽略」的 bug |
| **控制台开关乐观更新** | CDP 连拍三态：点之前 / 点下去之后 / 板端确认之后 | 绿"开" → 橙"关·待确认" → 灰"关"，**pending 与"关"颜色不撞** |

> 复现：`scripts/compare_eval.py`（检测前后对拍）、`scripts/run_4ch_gate_ab.sh`（两种拓扑的公平 A/B）、
> `scripts/console_shot.py --click mpp`（控制台三态连拍）。

## 已知限制（请一并阅读）

1. **12 路 @25 fps 需 4 块板 × 3 路**，单板 4 路 @25 fps 不可行（NPU 超载 8%，必然掉帧）
2. 新能源**两行车牌**在流水线级读出序号部分，省份字需专用车牌检测器
3. **IPM 标定值与机位强绑定**，换机位必须重新标定，否则测速距离全错
4. 生产检测模型**尚无人工真值标注集**，精度以 teacher-student 一致性（mAP@0.5 = 87.27%）为口径
5. `ebike_int8.rknn` 由 toolkit 2.5.0 编译，板端运行时 2.3.2 **加载会失败**，请用 `ebike_int8_rk2332.rknn`
