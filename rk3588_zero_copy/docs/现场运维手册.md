# 现场运维手册（极简版）

> 面向：现场运维 / 远程支持
> 完整规范见 `PRODUCTION_GUARD.md`；本手册只留**每天真会用到的**。

---

## 一、排查：系统是不是卡死了？

**一条命令**：

```bash
cd /home/seeed/rk_deploy/rk3588_zero_copy
sudo scripts/gate_health.sh
```

直接给结论：**正常 / 可疑 / 卡死**，并打印服务状态、日志心跳、各路帧号、内存水位、最近告警。

| 结论 | 含义 | 下一步 |
|---|---|---|
| **正常** | 一切正常 | 不用管 |
| **可疑** | 日志或某一路帧号停了一阵 | 再跑一次；持续可疑就看下面的日志 |
| **卡死** | 服务没跑 / 日志停 > 5 分钟 / 某路帧号停 > 3 分钟 | `sudo systemctl restart rk-gate` |

> 看门狗用的就是这套判据 —— 它报"卡死"时会**自动**重启，你手动 restart 只是不放心时再确认一次。

### ⚠️ 看门狗**不会**做什么（重要）

| 情况 | 看门狗的反应 | 原因 |
|---|---|---|
| 进程崩溃 / 被 OOM 杀掉 | **自动拉起** | `Restart=on-failure` + 看门狗双保险 |
| 启动失败（配置错、模型丢） | **带退避自动拉起** | `Result=exit-code` → 判定为"该拉起" |
| 业务卡死（进程活着但不干活） | **自动重启** | L1/L2 心跳判据 |
| **`systemctl stop` 被人为停掉** | **不拉起** | `Result=success` → 判定为"运维有意停的"，尊重意图 |

**所以：有人误 `systemctl stop` 之后忘了 start，服务会一直停着，看门狗不会管。**
无人值守的现场要么约定"停服务必须先 `touch /run/rk-gate/paused`"（有标记时看门狗彻底闭嘴，
状态一目了然），要么安排定期 `gate_health.sh` 巡检。

## 二、维护与升级

### 1）要停服务做维护（调试、换配置、换模型）

```bash
sudo touch /run/rk-gate/paused     # ① 先让看门狗闭嘴（维护期间它别插手）
sudo systemctl stop rk-gate        # ② 停服务
...                                 # ③ 做你的事
sudo systemctl start rk-gate       # ④ 恢复
sudo rm /run/rk-gate/paused        # ⑤ 解除沉默
```

> **第 ① 步别省**：没有它，看门狗会把停掉的服务又拉起来。
> （单纯 `systemctl stop` 一般不会被拉起，但加了标记是万无一失的做法。）

### 2）改配置（相机地址、模型、帧率、核绑定…）

全部在**一个文件**里，改完重启即可：

```bash
sudo vi /home/seeed/rk_deploy/rk3588_zero_copy/config/gate.env
sudo systemctl restart rk-gate
sudo scripts/gate_health.sh          # 确认起来了
```

### 3）升级程序（换二进制）

```bash
sudo touch /run/rk-gate/paused
sudo systemctl stop rk-gate
# ... 替换 build/rk_gate ...
sudo systemctl start rk-gate
sudo rm /run/rk-gate/paused
```

### 4）改守护配置本身（unit / 看门狗阈值 / 预检项）

```bash
cd /home/seeed/rk_deploy/rk3588_zero_copy
# 改 scripts/systemd/*.service 或 scripts/gate_watchdog.sh
sudo scripts/install_gate_service.sh     # 重装(会 restart 服务)
```

`install_gate_service.sh` 是**幂等**的：反复跑安全，每次都会把 unit 覆盖回仓库里的版本、清掉遗留的 drop-in、重启服务。

### 5）彻底卸载（换回手动跑）

```bash
sudo scripts/install_gate_service.sh --uninstall
```

零残留：unit / logrotate 规则 / 标记文件 / 锁全部清掉。日志默认保留（是证据），要一起删加 `--purge-logs`。

## 三、日志在哪看

| 看什么 | 路径 / 命令 |
|---|---|
| **业务日志**（推理统计、车牌、MQTT） | `/var/log/rk-gate-error.log` |
| stdout（预检结果、启动参数） | `/var/log/rk-gate.log` |
| **看门狗告警**（卡死/重启/水位） | `/var/log/rk-gate-alerts.log` |
| 启动前预检结果 | `/var/log/rk-gate-preflight.log` |
| systemd 层面的日志 | `journalctl -u rk-gate -n 100` |
| 崩溃现场取证包 | `logs/crash_<时间戳>.tar.gz` |

实时跟着看：

```bash
tail -f /var/log/rk-gate-error.log
```

> ⚠️ 本板 journald 是 `Storage=volatile`，**重启即丢** —— 所以业务日志一律落文件，
> 不要只靠 `journalctl` 找证据。

## 四、一句话速查

```bash
cd /home/seeed/rk_deploy/rk3588_zero_copy

sudo scripts/gate_health.sh          # 体检: 正常/可疑/卡死
sudo systemctl restart rk-gate       # 拉起
sudo touch /run/rk-gate/paused       # 让看门狗闭嘴(维护时)
sudo rm /run/rk-gate/paused          # 恢复看护
tail -f /var/log/rk-gate-error.log   # 看业务日志
tail -f /var/log/rk-gate-alerts.log  # 看告警
```
