# RK3588 系统能力对比表

> 全部数据均为 **RK3588 板端实测**(1920x1080 / H.264 / 25fps 相机源)。
> 采集时间 2026-11-10 ~ 2026-11-13, 原始数据见文末"数据出处"。

---

## 一、总览: 三种配置的能力对比

| 指标 | **hw**<br>MPP+RGA+NPU | **npu**<br>CPU解码+CPU预处理+NPU | **cpu**<br>全关 | 备注 |
|---|---|---|---|---|
| 解码方式 | VPU 硬解 (MPP) | CPU 软解 (FFmpeg) | CPU 软解 | |
| 预处理 | RGA 硬件 | OpenCV CPU | OpenCV CPU | |
| 检测 | NPU INT8 | NPU INT8 | 不做 | |
| **FPS** | **37.1** | 16.9 | 46.8¹ | 相机上限 25, 基准跑离线图集 |
| 解码 (ms/帧) | **0.50** | 16.39 | 12.65 | |
| 预处理 (ms/帧) | **2.41** | 18.36 | 8.71 | |
| 推理 (ms/帧) | 23.60 | 23.91 | — | |
| 后处理 (ms/帧) | 0.41 | 0.40 | — | |
| **单帧合计 (ms)** | **26.92** | 59.06 | 21.35 | |
| 相对基线 | **1.00×** | 0.45× | 0.79× | cpu 行不做检测, 不可直接比¹ |

> ¹ **cpu 行的 FPS 没有可比性**: 它关闭了 NPU, 整条链里**没有检测**,
> 它的 "FPS" 只代表"取流+解码+预处理"的速度。要做纯 CPU 检测需要另有一个 CPU 版检测器。

## 二、流水线逐段耗时(生产路径, 实时相机)

### 2.1 MPP 硬解 + RGA + NPU(**生产配置**)

| 阶段 | 硬件 | 耗时 (ms) | 占帧间隔 (40.02ms) |
|---|---|---|---|
| 解码等待(阻塞在取流) | — | 8.42 | 21% |
| 解码 | **VPU** | **0.49** | 1% |
| 预处理 NV12→RGB888 | **RGA** | **2.31** | 6% |
| 推理(YOLO+LPRNet) | **NPU** | **28.33** | 71% |
| 后处理(DFL+NMS+跟踪+测速) | CPU | 0.46 | 1% |
| 画框+显示 | CPU | 0.00 | 0% |
| **整帧** | | **40.02** | **100%** |
| **我们的活儿** | | **31.59** | **79%** |
| **流水线 FPS** | | **24.99** | |
| **相机推送 FPS** | | **24.98** | ← 整帧耗时恰好等于源的间隔 |

### 2.2 FFmpeg 软解 + CPU 预处理 + NPU(降级配置)

| 阶段 | 硬件 | 耗时 (ms) | 对比硬解 |
|---|---|---|---|
| 解码等待 | — | 0.38 | |
| 解码 | CPU | **18.42** | **37.6×** ❌ |
| 预处理 | CPU(OpenCV) | **11.42** | **4.9×** ❌ |
| 推理 | NPU | 26.37 | 1.07× |
| 后处理 | CPU | 0.48 | 1.04× |
| **整帧** | | **57.07** | **1.43×** ❌ |
| **我们的活儿** | | **56.69** | 占帧间隔 **99%**(算力打满) |
| **流水线 FPS** | | **17.52** | 0.70× |

> 软解路径的两个致命点: CPU 解码 18.42ms, 以及 **RGA 拿到 CPU 指针后退回 OpenCV**(11.42ms)。
> 同一个 RGA, 喂 dma-buf 是 2.31ms, 喂 CPU 指针是 11.42ms —— **零拷贝的价值就在这 5 倍**。

## 三、硬件加速比(实测)

| 对比项 | 快路径 | 慢路径 | **加速比** |
|---|---|---|---|
| **视频解码** | VPU 硬解 (MPP) | CPU 软解 (FFmpeg) | **37.6×** (0.49 vs 18.42 ms) |
| **图像预处理** | RGA (dma-buf 源) | OpenCV CPU | **7.6×** (2.41 vs 18.36 ms) |
| **图像预处理** | RGA (dma-buf 源) | OpenCV CPU(软解路径实测) | **4.9×** (2.31 vs 11.42 ms) |
| **模型推理** | NPU INT8 | — | (无 CPU 对照) |
| **模型推理** | NPU INT8 | NPU FP16 | **2.9×** (23.6 vs 68.4 ms) |

### 零拷贝链路的单帧成本

| 环节 | 走 dma-buf(生产) | 走 CPU 内存(降级) |
|---|---|---|
| 解码 → 预处理 | 0 次拷贝 | 1 次整帧拷贝 |
| 预处理 → 推理 | 0 次拷贝 | 1 次整帧拷贝 |
| 整帧额外 CPU 拷贝 | **0 次** | **2 次** (1920×1080×3 = 6MB/次) |

## 四、硬件负载(生产路径, 单实例)

| 单元 | 负载 | 说明 |
|---|---|---|
| NPU Core0 | **48~50%** | 检测模型 + 车牌模型(串行) |
| NPU Core1 | **0%** | 单实例默认只用一个核 |
| NPU Core2 | **0%** | 同上 |
| VPU (rkvdec) | **1.9%** | 硬解几乎空转 |
| RGA | 0%(本内核无 `/sys/kernel/debug/rga/load`) | 由 rktop 面板可见 |
| CPU (8 核合计) | **21.6%** | ≈1.7 核 |
| 大核 CPU 频率 | 1200~1800 MHz | ondemand 调度 |
| NPU 频率 | 1000 MHz | 固定 |

**判读: 没有任何硬件单元打满, 流水线却卡在 25 FPS → 上限是相机源。**

## 五、温度与降频(夜间长跑实测)

| 传感器 | 平均 | 最高 | 触发降频 |
|---|---|---|---|
| NPU (npu-thermal) | 37.0 °C | **37.9 °C** | ❌ 无 |
| SoC (soc-thermal) | 37.4 °C | **39.8 °C** | ❌ 无 |
| 大核 CPU (bigcore0/1) | 37.5 °C | **38.8 °C** | ❌ 无 |
| 小核 CPU (littlecore) | 38.3 °C | **40.7 °C** | ❌ 无 |
| CPU 频率最低点 | — | 1008 MHz | ondemand 正常调频, **非温控降频** |

> 温度距离典型降频阈值(85~95°C)还有 **45°C 以上** 余量。
> 板子在 25fps 轻负载下非常凉; 即便跑满 64fps 的并行检测, 实测温度也无明显变化。

## 七、NPU 多核调度能力

| 策略 | 单帧墙钟 | FPS | Core0 | Core1 | 可用? |
|---|---|---|---|---|---|
| auto (基线, 单实例) | 30.0~31.8 ms | 31~33 | 38.4% | 0% | ✅ 默认 |
| A: YOLO→core0 + LPR→core1 | 30.0~31.9 ms | 31~33 | 38.4% | 0% | ❌ 串行分核无意义 |
| C: YOLO→`CORE_0_1` 双核模式 | 30.4~30.5 ms | 32.8 | 37.3% | 4.1% | ❌ 对该模型无效 |
| B-seq: 两实例**交替** | 30.2~31.3 ms | 31~33 | 18.7% | 18.9% | ❌ 数学上不可能更快 |
| **B-par: 两实例双缓冲并行** | **15.4~15.6 ms** | **64~65** | 28.1% | 28.7% | ✅ **1.95×** |

**已落地**: `--npu-pipe 2`(默认关闭)。正确性: 同输入下串行/并行检测结果 **15/15 一致**。

## 八、模型精度能力

| 模型 | 精度 | 与 FP16 的量化损失 | 车牌准确率 | NPU 耗时 |
|---|---|---|---|---|
| yolov8n (同源 ONNX) | INT8 | 分数漂移 **0.04%**, 框漂移 **0.56px**, 类别逐格一致 97.5% | — | 18.3~23.6 ms |
| yolov8n (同源 ONNX) | FP16 | 基准 | — | 54.1 ms |
| ebike_int8_rk2332 (生产) | INT8 | 无法对照(无源模型) | — | 24.3 ms |
| lprnet_finetuned (生产) | INT8 | 无法对照(无源模型) | 真实绿牌 **0/1**(非量化问题) | 1.03 ms |

**判定: INT8 精度损失 << 2% → 可直接交付。**
