## 为什么不删掉

代码保留，作为**最终业务形态的设计参考**（4 层解耦、批处理、多核分工的思路是对的）。
但现在**一个字节都不许改**——改了会让"带病复现"的对照关系失效。

## 为什么冻结（不只是"规矩"，是技术判断）

1. **它就是"多路/并发开发"本身**：12 个解码线程 + 有界队列 + NPU 批处理 + 多核分工。
   规则明令在根因定位前停止并发开发。
2. **ctypes 是黑盒，不能用于硬挂死排查**：
   - ctypes 没有边界检查，结构体布局对不上就是静默的内存破坏；
   - 硬挂死是内核级故障，需要看到"指针 + 物理地址 + fd"这三样东西；
     ctypes 把它们全藏起来了，崩溃时拿不到可归因的证据。
   - 本轮 D1 批复也是这个判断：**必须用 C++ 看到最底层的指针和内存布局**。
3. **同时存在两个高风险实现会让归因彻底失效**：如果 C++ 侧和 Python 侧都能崩，
   就无法用"只跑一个模块"来二分到底是哪一层的问题。
